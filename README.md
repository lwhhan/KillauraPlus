# 杀戮光环++ / Killaura++

**Minecraft 1.20.1 · Fabric · 纯客户端**

一个**纯客户端** Fabric 模组：按 **R 键**自动攻击以玩家为中心、指定距离内**并且看得见**的生物与玩家（按距离由近到远逐一攻击）。主手拿弓时可切换为弓箭模式自动瞄准射击。

设置入口是模组自带的**独立设置界面**：按 **K 键**（可改）打开；装了 **Mod Menu** 的话，也能在模组列表里点配置按钮进入。Mod Menu 是**可选**的，不装照样能用。

---

## ⚠️ 关于本模组与「杀戮光环」的关系

这个模组**早期**确实使用了 [yiyuyan/Killaura-1.20.1](https://github.com/yiyuyan/Killaura-1.20.1)（Forge 1.20.1 版杀戮光环）的**部分代码**作为起点——主要是最初的按键注册、配置读写和基础攻击循环骨架。

**但从那之后变化非常大**，现在版本里绝大部分逻辑都是重写的：

- **弓箭模式整套**是后来从零写的：追踪箭、按血量算需要几箭（含护甲减伤）、逐 tick 分帧发射、目标队列调度，原项目没有这些
- **目标筛选**重写：`Enemy` 判定（覆盖幻翼、史莱姆、恶魂、潜影贝等）、3 格内免视线检测、箭出生点射线
- **设置界面**（`KillauraConfigGUI`）是独立实现，不是原项目的 GUI
- **攻击循环**改成服务端线程异步执行 + 队列调度 + 防重入，和原来的同步实现是两套东西
- 模组 ID、包名、类名、配置项、默认值、按键全部换过

**所以请不要把「杀戮光环++ / Killaura++」和「杀戮光环 / Killaura」当成同一个模组。** 它们解决的问题相似，但代码已经是两条路线，功能、配置、行为差异明显，出问题也不要用原模组的文档来对照排查。

原始的 Forge 实现作者是 **yiyuyan**，这部分起点在此致谢。

## 主要功能

| 功能 | 说明 |
|------|------|
| 触发攻击 | 按 **R 键**切换开关，开启后自动搜索周围实体并持续攻击 |
| **设置界面** | 按 **K 键**（可改）打开，界面内也能直接改这个键；装了 Mod Menu 也能从模组列表进入（可选，非必需） |
| 自动排序 | 按与玩家的距离由近到远依次攻击（攻击最近的先） |
| 近战攻击距离 | 可配置近战的搜索半径（默认 3 格，范围 1~100） |
| 弓箭攻击距离 | 弓箭模式**独立**的搜索半径（默认 20 格，范围 1~100），比近战远 |
| **视线检测** | **只打看得见的目标，不能穿墙**。相当于「把手变长」，而不是无视地形 |
| **追踪箭** | 箭飞出去之后每 tick 重新指向目标**头部**，目标怎么跑都躲不掉；只露脑袋的怪也能打到 |
| **按血量定箭数** | 算出单发伤害，只射「刚好打死」的箭数，不多射也不被硬上限卡节奏 |
| **不挡视野** | 箭的出生点从眼睛下移到胸口以下，第一人称看不到出射瞬间，飞出去才看得见 |
| **分帧射击** | 队列受「同时攻击数量」硬性约束，目标多时分摊到多个 tick 射出，不在一帧内堆出上百个箭实体 |
| **箭矢自动回收** | 模组射出的箭最多存活 5 秒就消失，不会在地面堆几百支拖慢渲染 |
| 摇手动画 | 可开关攻击时是否播放挥臂动画（单机已在客户端线程直接播放） |
| 目标类型 | 可选「全部 / 只打玩家 / 只打怪物 / 只打动物」；**选什么只打什么，不会回退去打其它类型** |
| 攻击间隔 | 可配置每轮攻击的间隔（tick，1 ~ 无上限） |
| 同时攻击数量 | 每轮最多同时攻击的目标数（1~100）。设 1 就是严格只打一个，打死或跑掉才换下一个 |
| 弓箭模式 | 主手为弓时改用弓箭自动瞄准射击，保留原版箭矢消耗、耐久、附魔与音效 |
| 弓箭立即开火 | 关：等满蓄力（20 tick）再射；开：按攻击间隔高频连射 |
| 服务器模式 | 多人服务器中通过发包方式近战攻击；默认关闭，可在配置中开启 |
| 单机模式 | 单人游戏直接调用服务端攻击逻辑，绕开原版 6 格距离校验 |

## 视线规则

本模组只取消原版的**攻击距离**限制，**保留可见性要求**：

- 从**箭的实际出生点**（眼睛稍下移 0.8 格、沿瞄准方向前移 0.25 格）向目标做方块射线检测（检测有碰撞箱的方块，水和岩浆不阻挡视线）。用箭的出生点而不是眼睛，是为了和箭真正飞出去的轨迹一致，避免「箭其实飞得过去、却被判成看不见」。
- 分别向目标「眼睛」和「躯干中点」各打一条射线，任意一条没被挡住就算看得见——矮个子目标不会因为眼睛被矮墙挡住而误判。
- 被墙、石头、玻璃、树叶、地板等**任何有碰撞箱的方块**挡住的目标**一律不选**，不管距离多近。
- **树叶算遮挡**：目标躲在树冠后面（视线被叶子挡住）时，不会被触发攻击。
- 近战和弓箭**共用同一套筛选规则**，所以弓箭也不会隔着墙、隔着树叶射。
- **3 格内的目标直接算可见**，完全跳过射线检测——贴脸的怪（尤其是站在你正下方、被自己脚下的台阶或方块挡住视线的）不会被误判成「看不见」。这条是专门为修「怪在脚底下却一直不打」加的。
- 如果周围的目标全都看不见，就不会攻击，每 2 tick 重新检测一次。

一句话：**看得见才打，看不见不打；手变长，但不穿墙也不穿树叶。**

## 追踪箭

原版箭是抛物线飞行，照直线瞄会打空：

| 距离 | 原版直线瞄准的下坠量 |
|------|------|
| 10 格 | 约 0.21 格 |
| 20 格 | 约 0.99 格 |
| 30 格 | 约 2.42 格 |

目标躯干高度只有 1.8 格，20 格开外直线瞄基本必脱靶。之前用的是「弹道反解 + 移动预判」，但再怎么算，目标在箭飞行的半秒里变向、起跳、绕树，照样会空。

现在直接改成**追踪箭**：

- **发射**：朝目标**头部（眼睛高度）**射出去，不做弹道补偿、不做移动预判。
- **飞行中修正**：每 tick 把箭的速度方向重新指向目标**头部**，速度大小固定 **3.0 格/tick**（原版满蓄力初速）不衰减 —— 箭走的是直线追人，目标跑、跳、后退、侧闪都躲不掉。
- **打头不打身**：有些怪只露出一个脑袋（半身陷在洞里、站在矮墙后），瞄躯干中点的话箭会先撞在它身前的方块上。瞄准点取眼睛高度，始终落在碰撞箱内部，既能打到头，也不会从头顶擦过去。
- **命中确定**：快命中时清零目标的受伤无敌帧。原版受伤后 10 tick 内再受同等或更低伤害会被直接丢弃，不清零的话「两箭射死」根本不成立，第二箭会白飞。
- **不改视角**：直接用方向向量发射，全程不动玩家的 xRot/yRot，所以不会有任何视角抖动。
- **撞墙作废**：箭本身仍然不穿墙（与原版一致）。撞上方块插住后这一箭作废，给该目标记 **5 tick 冷却**，不会对着同一堵墙连续空射。

## 按血量决定射几箭

追踪箭每发必中、速度恒定、没有暴击的随机加成，所以**单发伤害可以精确算出来**（并且扣掉了目标护甲）：

```
单发伤害 = ceil(3.0 × baseDamage) 再按目标护甲减伤
baseDamage = 2.0（普通箭） + 力量等级 × 0.5 + 0.5（有力量时）
```

每轮开火前先算 `ceil(目标当前血量 ÷ 单发伤害)`，这就是杀死它需要的箭数；减去已经在飞的箭，剩下的才是这一轮该补的。

效果：

| 情况 | 行为 |
|------|------|
| 目标 2 箭就死 | 只射 2 箭，射完换下一个目标，不对着快死的怪继续输出 |
| 目标穿盔甲 | 按护甲减伤后的实际伤害算，箭数不会算少，一轮就能打死 |
| 箭撞墙作废 | 血量没降，5 tick 后就补射 |

**需要的几支箭在同一轮里连射完，不用等下一轮。** 每支箭之间隔一个「攻击间隔」：

- 攻击间隔 = 1 → 每 tick 一支，需要的箭几乎瞬间射完
- 攻击间隔 = 10 → 每半秒一支
- 没开「立即开火」→ 每支之间隔满蓄力时间（20 tick）

间隔完全由设置项决定，你设多快就多快。

为什么不是把需要的箭全塞进同一个 tick：原版受伤后有 10 tick 判定窗口，两支箭如果**同一 tick** 命中，第二支会被直接丢弃、等于白射。按间隔逐支射，命中自然错开，配合追踪时的无敌帧清零，每一箭都真正结算。

## 弓箭近距离

- 箭撞上方块后 **5 tick** 就重试（原来是 20 tick）。怪贴在脚边、或者你站在台阶边上打低处的怪，不会再出现「半天不出箭」。
- 视线判定改成从**箭的实际出生点**出发，和真实弹道一致，不会再出现「看得见却不出箭」。

## 性能优化

周围怪很多、目标数开到上百时，弓箭模式的开销主要来自几处：追踪修正、瞬时箭实体数量、地面残留箭、空目标空转。对应做了五组优化。

### 1. 追踪修正几乎零成本

追踪模式开火时不需要提前解弹道，所以原来那套「方块轨迹检测 + 仰角求解」在开火路径上完全不走（代码保留在类里，作为抛物线模式的退路）。每 tick 的追踪修正只对**在飞中的箭**做一次向量运算，在飞的箭一般只有几支，开销可以忽略。

### 2. 分帧射击 + 队列硬上限

**关键点：`同时攻击数量` 是硬上限，队列长度永远不超过它。**

```
本轮最多 100 个目标
  → 队列裁剪到 ≤ targetCount
  → 每 tick 最多射 6 支
  → 剩下的下一 tick 继续
  → 队列空了，才开始算攻击间隔
```

- **队列不会越滚越长**：设 `targetCount = 1` 就真的只有一个目标在队列里。目标换人时旧目标会被裁掉（`pollLast`），新目标补进来，永远不超上限。之前「设 1 却同时打很多目标」就是队列没设上限导致的，已修。
- 100 个目标约 17 tick（不到 1 秒）射完，帧率平稳，看到的是连续射箭。
- `targetCount = 1~6` 时一轮内就射完。
- **队列非空时每 tick 都继续搜索新目标**，不会被排队中的旧目标挡住——脚下刚冒出来的怪也能立刻进队。
- 关掉光环、切维度、收弓都会清空队列。
- 队列的取出/放回全部在**服务端线程**里做，客户端不读队列状态，所以不会出现「看起来卡住、重启才恢复」的异步竞态。

### 3. 目标搜索优化

| 项 | 优化前 | 优化后 |
|------|--------|--------|
| 类型过滤 | 先查全部实体，再 filter | **放进实体查询的 predicate**，候选列表一开始就小 |
| 距离计算 | 排序比较时反复调用 | **预计算一次**再排序 |
| 视线检测次数 | 固定 32 次（64 条射线） | **`max(8, targetCount × 2)`**，最多 32 次 |

要 1 个目标时只查 8 个候选（16 条射线），要 5 个查 10 个，不再固定查满 32 个。

### 4. 箭矢自动回收

原版箭落地后要累计 **1200 tick（60 秒）** 才消失。弓箭模式持续开火时，地面上会堆几百支箭，每一支都要 tick、参与碰撞检测、参与渲染 —— 这是实测掉帧的主要来源之一。

| 项 | 优化前 | 优化后 |
|------|--------|--------|
| 箭的存活时间 | 落地后 60 秒 | **生成后 5 秒**（`MOD_ARROW_LIFETIME_TICKS = 100`） |
| 地面堆积量 | 连射几分钟堆几百支 | **稳定在几十支以内** |
| 回收检查 | — | 每 20 tick 检查一次，只处理模组自己射出的箭 |

细节：

- 只回收**本模组射出的箭**，玩家手动射的箭、骷髅射的箭、其他模组的弹射物一概不碰。
- 箭命中后自行 `discard` 的，记录会在下一轮检查时清掉，表不会越滚越大。
- 回收定时器**不依赖光环开关**：关掉光环后，地上残留的箭照样会被清完。
- 切维度时清空回收表，避免旧维度的实体 ID 在新维度误匹配到别的实体。

### 5. 空目标时的重查间隔

原来搜索不到可见目标时写的是 `cooldownRemaining = 1`，本意是「隔一下再查」，但 tick 开头会先递减，当帧就归零 —— **等于没冷却，每 tick 都在做一次全量实体扫描 + 最多 16 次射线检测**。周围怪全被墙挡住、或者圈里根本没怪时，这份开销一直白白烧着。

| 项 | 优化前 | 优化后 |
|------|--------|--------|
| 空目标时的搜索频率 | 每 tick（20 次/秒） | **每 5 tick（4 次/秒）** |
| 空转开销 | 持续满负荷 | 降到 1/5 |

5 tick（0.25 秒）的延迟人眼基本感觉不到，但怪一进圈最多只晚 0.25 秒开始打。

## 箭不挡视野

原版箭从眼睛位置射出，第一人称视角下箭头就贴在镜头正前方，连射时一堆箭头糊在屏幕中央。

本模组把箭的出生点从眼睛位置**下移 0.8 格**、沿瞄准方向前移 0.25 格（相当于从胸口/腰部射出）：

- 第一人称视角看不到箭的出生瞬间（已经在视野下边缘之外）
- 箭飞出一段距离后才进入视野，正常可见
- 出生点不影响追踪：箭生成后立刻被指向目标，起点高低只决定第一段轨迹

## 目标类型规则

「目标类型」是**硬过滤**，不是优先级排序：

| 选择 | 效果 |
|------|------|
| 全部 | 范围内所有可见的存活实体（玩家 + 怪物 + 动物）都会被打 |
| 只打玩家 | **只有玩家**会被攻击，怪物和动物即使在旁边也不碰 |
| 只打怪物 | **只有敌对生物**会被攻击——僵尸、骷髅、苦力怕、蜘蛛、幻翼、史莱姆、岩浆怪、恶魂、潜影贝这些都算，动物和玩家即使在旁边也不碰 |
| 只打动物 | **只有动物**会被攻击，怪物和玩家即使在旁边也不碰 |

选某一类型后，范围内没有该类型目标时就**什么都不打**，不会退回打最近的其他目标。

> 「怪物」的判定用的是原版的 `Enemy` 接口，**不是** `Monster`。幻翼（Phantom）、史莱姆、岩浆怪、恶魂、潜影贝都不继承 `Monster`，用 `Monster` 判会全部漏掉——之前「幻翼不识别为怪物」就是这个原因，现已统一改成 `Enemy`。

## 服务器启用是什么

这个开关**只影响多人服务器（联机到别人的服务器）**，单人游戏完全不看它。

| 场景 | 是否受「服务器启用」影响 | 实际行为 |
|------|------------------------|----------|
| 单人游戏（自己开的世界） | ❌ 不受影响 | 走本地服务端直调，`reach` 调多大就多大，弓箭模式也正常 |
| 联机到别人的服务器 | ✅ 受它控制 | 关闭时：只弹提示，不攻击<br>开启时：发原版攻击包过去，由对方服务端校验 |

**默认关闭的原因：**

1. 原版服务端收到攻击包时会做硬编码的 6 格距离校验（`distanceToSqr < 36.0`），超出直接丢弃。所以 `近战攻击距离` 在服务器上**调多大都只有 6 格有效**。
2. 大多数公共服务器装了反作弊，高频发包、超距攻击会被判定为作弊，轻则拉回重则踢出封号。
3. 弓箭模式在服务器上完全不可用（需要完整的拉弓-释放时序和视角同步，无法可靠模拟），会提示改用近战。

所以：**自己开单人世界玩，这个开关不用管；上别人服务器想用近战，才需要打开，并且清楚风险。**

## 使用方式

1. 安装 **Fabric Loader** 和 **Fabric API**，把本模组 jar 放入 `mods` 文件夹。
2. **Mod Menu 可选**：不装也能用 K 键打开设置；装了会多一个「模组列表 → 配置」入口，两个入口进的是同一个界面。
3. 进游戏后，按 **R** 开关杀戮光环。
4. 按 **K**（可改）打开设置界面，可调整近战距离 / 弓箭距离 / 攻击间隔 / 同时攻击数量 / 目标类型 / 摇手 / 弓箭模式 / 弓箭立即开火 / 服务器启用，以及「打开设置」这个按键本身。
5. 配置自动保存于 `config/killaura-config.txt`（格式：`近战距离;摇手;服务器启用;目标类型;攻击间隔;同时攻击数量;弓箭模式;弓箭立即开火;弓箭距离`）；按键绑定由原版保存在 `options.txt`。

## 按键

| 按键 | 功能 | 怎么改 |
|------|------|--------|
| R | 开关杀戮光环 | 选项 → 控制 → 按键绑定 → 杀戮光环 |
| K | 打开设置界面 | 同上，或在设置界面里点「设置界面按键」，再按新键 |

两个键都注册成了标准 `KeyMapping`，所以能像原版按键一样在控制设置里改、也能被其他模组检测到冲突。

## 弓箭命中率

追踪箭是「必中」的：箭飞出去之后每 tick 都会被重新指向目标头部，不存在打偏、打空、被移动目标甩掉的情况。之前那套「散布 / 预判迭代 / 垂直折扣 / 在飞上限」的调参全部不再需要。

唯一会让箭落空的情况是**中间有方块挡着**（墙、树、地形）。这种情况靠筛选阶段的视线检测 + 撞墙后的 5 tick 冷却兜住，不会一直空耗箭矢。

## 箭的粒子

模组射出的箭**不再喷暴击粒子**。

原版满蓄力射箭会给箭打上暴击标记（`setCritArrow(true)`），箭飞行时沿轨迹持续喷白色 `CRIT` 粒子，连射时像一条粒子柱从身前一直拖出去，既糊视野又费性能。本模组把它关掉了——只影响粒子表现，**伤害、弹道、音效完全不变**。

## 配置项

| 配置 | 键 | 默认 | 说明 |
|------|-----|------|------|
| 近战攻击距离 | `meleeReach` | 3 | 近战攻击的搜索半径（1~100） |
| 摇手 | `swingHand` | true | 攻击时是否播放挥臂动画 |
| 服务器启用 | `enabledInServer` | false | 多人服务器中是否发包攻击 |
| 目标类型 | `targetPriority` | ANY | ANY / PLAYER / MONSTER / ANIMAL，选什么只打什么 |
| 攻击间隔 | `attackInterval` | 10 | 单位 tick（20 tick = 1 秒），范围 1 ~ 无上限 |
| 同时攻击数量 | `targetCount` | 1 | 每轮同时攻击的目标数（1~100） |
| 弓箭模式 | `bowEnabled` | false | 主手为弓时是否改用弓箭输出 |
| 弓箭立即开火 | `bowInstantFire` | false | false=等满蓄力，true=按攻击间隔射 |
| 弓箭攻击距离 | `bowReach` | 20 | 弓箭模式的搜索半径（1~100），与近战距离独立 |

> 旧版配置（3~8 字段）可直接兼容：缺少的字段自动按默认值处理。
> 早期版本的 `reach` 字段位置现对应 `meleeReach`，含义不变。

## 弓箭模式说明

- **触发条件**：`弓箭模式` 开启，且主手物品为**弓**（`minecraft:bow`）。主手不是弓时仍走普通近战逻辑。
- **搜索距离**：弓箭模式使用独立的 `弓箭攻击距离`（默认 20 格），不受 `近战攻击距离` 影响。
- **射击方式**：手动复刻原版发射流程，箭矢消耗、弓的耐久消耗、力量 / 冲击 / 火矢 / 无限附魔、音效全部与原版一致；箭改为追踪飞行，且不喷暴击粒子。
- **力量**：始终按满蓄力（1.0）结算，所以「立即开火」是高频满伤害连射，而不是弱箭。
- **箭矢消耗**：普通生存按每箭消耗 1 支；无限附魔射普通箭不消耗（光灵箭、药箭照常消耗）；创造模式不消耗。
- **多目标**：`同时攻击数量` 生效，最多 100 个目标全部都会射到（会消耗对应数量的箭）。目标多时按**每 tick 最多 6 支**分批射完，不会一次卡顿。
- **节奏**：
  - `弓箭立即开火 = 否` → 队列射完后等 20 tick（1 秒，满蓄力时间）再开始下一轮
  - `弓箭立即开火 = 是` → 队列射完后等 `攻击间隔` tick 再开始下一轮
  - 队列还没射完时不等冷却，连续逐 tick 发射
- **限制**：弓箭模式**仅支持单人游戏**。多人服务器需要完整的拉弓-释放协议时序与视角同步，无法可靠模拟，此时会提示改用近战模式。

## 构建

```bash
./gradlew build
# 产物位于 build/libs/杀戮光环++Killaura++-1.20.1-1.0.0.jar
```

Windows 用 `.\gradlew.bat build`。

需要 JDK 17+（新版 Loom 构建过程需要 JDK 21，产物字节码为 Java 17，可在任意 Java 17+ 运行环境使用）。

**Mod Menu 是软依赖，仓库里不用提交它的 jar。** `build.gradle` 里用的是 `modCompileOnly`，编译期从 [Terraformers maven](https://maven.terraformersmc.com/releases/) 拉 `com.terraformersmc:modmenu:7.2.2`；如果你本地 `libs/` 下放了 jar，会优先用本地的（离线也能编）。第一次构建需要联网拉一次，之后 Gradle 会缓存。
